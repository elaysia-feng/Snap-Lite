# Snap-Lite v1.3.3-beta.7

Beta test focus:
- Report F1 / Ctrl+Shift+F hotkey registration failures individually instead of collapsing them into a single notice.
- Restore missing tray notification flags (NIF_MESSAGE | NIF_ICON | NIF_TIP) so toast popups deliver again.
- Validate GDI+ PNG clipboard commit status and free the PNG buffer when `RegisterClipboardFormatW("PNG")` is unavailable.
- Treat `swprintf_s` return value as a fatal error and clear the filename buffer when formatting fails.
- Drop `RemoveWindowSubclass` before destroying the editor `EDIT` control to stop subclassed cleanup racing with native focus loss.
- Only snapshot text state for undo when the editor text control is idle, then re-record after color/size changes.
- Bounds-check the secondary toolbar index against the actual rendered rect list before dispatching a click.
- Track partial GDI failures during selection restore so source/target DCs and the screen DC are always released.
- Promote shape drawing state from module-level globals to per-`SnipWindow` members and friend the themed GDI shims so concurrent snip windows cannot clobber each other.
- Defensively `#undef` the Win32 macro hijack (CreateFontW, Rectangle, MoveToEx, LineTo, Polygon, Color, ...) before re-applying it inside `snip_window.cpp` so other translation units see the real API.
- Centralize the baked annotation red as `kDefaultAnnotationRed()` so it stays stable across themes.
- Destroy the editor `EDIT` window before clearing `textEdit_` so any re-entrant `EN_KILLFOCUS` short-circuits cleanly.
- Allow long paths in the pin save-as dialog via `OFN_ALLOW_LONG_PATHS` (guarded by `#if defined`).
- Rely on `BitmapHistory::Trim` for the undo stack size cap (size > 6 OR bytes > 32MB) and drop the redundant manual trim in `BeginEdit`.

Release trigger: publish after deterministic PE icon verification passes in Windows x64 CI.
